## Что это за бот

Бот — минимальный чат с Gemini Flash-Lite в личке Telegram. Пользователь пишет текст, бот отправляет его в модель и сразу начинает показывать ответ: текст «печатается» в чате с анимацией, как в ChatGPT или Claude. Когда генерация закончена, ответ остаётся в чате обычным сообщением с форматированием.

Главные возможности:

- Ответ Gemini Flash-Lite на любое текстовое сообщение.
- Живой стриминг ответа нативным механизмом Telegram (черновик сообщения с анимацией).
- Кнопка остановки генерации прямо в черновике.
- Форматирование итогового ответа (жирный, курсив, код, списки, ссылки).
- Автоматическая разбивка длинных ответов на несколько сообщений.

## Кто может пользоваться ботом

Бот приватный и работает по whitelist. Пользователь разрешён, если выполняется хотя бы одно правило:

- Его Telegram user ID — ID владельца бота.
- Его Telegram user ID есть в списке разрешённых ID.
- Его username (без `@`, без учёта регистра) есть в списке разрешённых usernames.

Актуальный whitelist хранится только в конфигурации на сервере и в этом документе не публикуется.

Бот работает только в личных чатах. В группах и каналах он ничего не делает.

## Команды для пользователя

| Команда | Кто может использовать | Что делает |
|---|---:|---|
| `/start` | whitelist | Показывает справку. |
| `/help` | whitelist | Показывает ту же справку, что и `/start`. |

Любой другой текст (не команда) считается вопросом к модели.

## Как задать вопрос

Пользователь просто пишет боту сообщение. Сразу после этого в чате появляется черновик с индикатором «Thinking…», затем в нём постепенно появляется текст ответа. Пока идёт генерация, Telegram показывает анимированные точки в конце черновика.

Когда модель закончила, черновик заменяется обычным сообщением с полным ответом. Итоговое сообщение отправляется как reply на вопрос пользователя.

Каждое сообщение обрабатывается независимо: бот не помнит предыдущие вопросы и ответы.

Если пользователь отправил новый вопрос, пока бот ещё отвечает на предыдущий, предыдущая генерация прерывается (то, что успело сгенерироваться, сохраняется в чате с пометкой ниже), и бот начинает отвечать на новый вопрос.

## Как остановить генерацию

Во время стриминга в черновике есть штатная кнопка Telegram «Stop». После нажатия бот прекращает запрос к модели и сохраняет в чате уже сгенерированную часть с пометкой в конце:

```text
⏹ Остановлено
```

Если к моменту остановки не было сгенерировано ни одного символа, бот отправляет только:

```text
⏹ Остановлено
```

## Длинные ответы

Одно сообщение Telegram вмещает до 4096 символов. Если ответ длиннее, бот завершает текущее сообщение на границе абзаца или строки (около 4000 символов), фиксирует его в чате и продолжает стримить продолжение в новом черновике. В итоге длинный ответ приходит несколькими последовательными сообщениями.

## Ошибки и ограничения

Если Gemini вернул ошибку или не ответил вовремя:

```text
Не удалось получить ответ от Gemini. Попробуй ещё раз чуть позже.
```

Если ошибка произошла в середине ответа, уже полученная часть сохраняется в чате, а сообщение об ошибке приходит следом.

Если модель отказалась отвечать (сработали фильтры безопасности) или вернула пустой ответ:

```text
Gemini не вернул ответ на этот запрос.
```

Если превышен лимит запросов в минуту:

```text
Слишком много запросов. Подожди минуту и попробуй снова.
```

Если пользователь прислал не текст (фото, голосовое, стикер, файл):

```text
Пока я понимаю только текстовые сообщения.
```

Пользователь не из whitelist на любое сообщение получает:

```text
Доступ закрыт.
```

## Что показывает `/help`

`/start` и `/help` показывают один и тот же текст:

```text
Привет. Я пересылаю твои сообщения в Gemini Flash-Lite и показываю ответ по мере генерации.

Просто напиши вопрос текстом.
• Ответ печатается в реальном времени, кнопка Stop в черновике останавливает генерацию.
• Каждое сообщение — отдельный запрос: я не помню предыдущий диалог.
• Длинные ответы приходят несколькими сообщениями.
• Понимаю только текст.

Модель: <имя модели>
```

`<имя модели>` — фактический ID модели из конфигурации, например `gemini-3.5-flash-lite`.

## Границы функциональности

Бот НЕ делает:

- Не хранит историю диалога и не передаёт модели контекст прошлых сообщений.
- Не обрабатывает фото, голосовые, документы и другие медиа.
- Не работает в группах, каналах и inline-режиме (стриминг черновиков Telegram доступен только в личных чатах).
- Не имеет команд выбора модели, системного промпта или температуры — всё задаётся конфигурацией на сервере.
- Не ищет в интернете и не вызывает инструменты модели.
- Не хранит тексты вопросов и ответов ни в базе, ни в логах.

## Техническая спецификация для реализации

Ниже — требования к реализации: runtime, Docker, env, handlers, алгоритм стриминга, интеграции и acceptance checklist.

### Детали: Цель и границы системы

Stateless-прокси: `text update → Gemini generateContent stream → sendMessageDraft (throttled) → sendMessage`. Нет базы данных, нет фоновых задач, нет persistent state. В памяти процесса держится только: таймстемпы запросов для rate limit и активная генерация на чат (для отмены).

### Детали: Архитектура

#### Runtime

- Язык: Python 3.12 (`python:3.12-slim`).
- Telegram framework: `python-telegram-bot` 22.x (`send_message_draft` есть нативно).
- Параметры `can_stop` / `keep_on_stop` и update `stopped_message_generation` появились в Bot API 10.3 и могут отсутствовать в PTB. Если PTB их не поддерживает нативно:
  - `sendMessageDraft` вызывается через `send_message_draft(..., api_kwargs={"can_stop": True})`.
  - `stopped_message_generation` читается из `update.api_kwargs` в `TypeHandler(Update, ...)`.
- Gemini SDK: `google-genai` (асинхронный клиент `client.aio.models.generate_content_stream`).
- Markdown → Telegram: `telegramify-markdown` (Markdown модели → MarkdownV2 + escaping).
- База данных: нет.
- Транспорт: long polling, `Application.run_polling(allowed_updates=[...])` с явным списком: `message`, `stopped_message_generation`.
- Concurrency: `Application.builder().concurrent_updates(True)` — генерации в разных чатах идут параллельно; stop-update должен обрабатываться, пока идёт генерация в том же чате.

Ожидаемая структура на сервере:

#### Основные переменные окружения

```env
BOT_TOKEN=

GEMINI_SYSTEM_PROMPT=

```

- `GEMINI_SYSTEM_PROMPT` пустой → `system_instruction` не передаётся.
- Обязательны: `BOT_TOKEN`, `GEMINI_API_KEY`, `OWNER_ID`. Без них процесс падает при старте с понятной ошибкой (без вывода значений).

### Детали: Модель доступа

Проверка выполняется до любого действия для каждого update (`message`, `stopped_message_generation`).

Разрешён, если хотя бы одно:

- `user.id == OWNER_ID`;
- `user.id ∈ ALLOWED_USERS`;
- `user.username.lower() ∈ {u.lstrip('@').lower() for u in ALLOWED_USERNAMES}` (если username есть).

Неавторизованный в личном чате → ответ `Доступ закрыт.` и `return`; в лог `WARNING` с `user.id` (без текста сообщения). Update не из `ChatType.PRIVATE` → игнор без ответа.

### Детали: Команды и зарегистрированные handlers

Активные команды:

```text
/start
/help
```

Активные handler-ы (порядок важен):

- `TypeHandler(Update, on_stop_generation)` в group `-1` — обрабатывает только update с `stopped_message_generation`, иначе ничего не делает.
- `CommandHandler(["start", "help"], help_command, filters=filters.ChatType.PRIVATE)`.
- `MessageHandler(filters.ChatType.PRIVATE & filters.TEXT & ~filters.COMMAND, on_text)`.
- `MessageHandler(filters.ChatType.PRIVATE & filters.COMMAND, help_command)` — неизвестная команда показывает справку.
- `MessageHandler(filters.ChatType.PRIVATE & ~filters.TEXT & ~filters.StatusUpdate.ALL, on_non_text)`.

Не должны регистрироваться: `InlineQueryHandler`, `CallbackQueryHandler`, любые JobQueue-задачи, handlers для групп.

### Детали: Help-текст

`/start` и `/help` — один и тот же текст из [Что показывает `/help`](#что-показывает-help), без `parse_mode`. `<имя модели>` = `settings.gemini_model`.

### Детали: База данных

Нет. Ничего не пишется на диск.

### Детали: Основные пользовательские потоки

#### Ответ на текстовое сообщение (`on_text`)

1. Проверить доступ.
2. Проверить rate limit (sliding window 60 с по `user.id`, `deque` таймстемпов, лимит `RATE_LIMIT_PER_MINUTE`). Превышен → текст лимита, `return`. Запрос учитывается в момент приёма.
3. Если в `active[chat_id]` есть генерация → вызвать её `cancel(reason="superseded")` и дождаться завершения (она финализирует свою часть с пометкой `⏹ Остановлено`).
4. Создать `DraftStreamer(chat_id, reply_to=message.message_id)`, записать в `active[chat_id]` (вместе с asyncio task).
5. `draft_id = random.randint(1, 2**31 - 1)`. Сразу `sendMessageDraft(text="", can_stop=True)` → в Telegram «Thinking…».
6. Итерировать `stream_answer(prompt)`; каждый чанк добавлять в буфер `current`.
7. Throttle: отправлять `sendMessageDraft(chat_id, draft_id, text=current[:4096], can_stop=True)` не чаще раза в `DRAFT_INTERVAL_MS` и только если текст изменился. Плейсхолдер из п. 5 не сдвигает throttle — первый реальный текст уходит сразу. Черновики отправляются plain text, без `parse_mode` (незакрытые маркеры Markdown ломают парсинг).
8. Split: если `len(current) > 4000` → `head, tail = split_text(current, 4000)` (резать по последнему `\n\n`, иначе `\n`, иначе пробелу, иначе жёстко на 4000). `head` финализировать (п. 10), `current = tail`, новый `draft_id`, продолжить стрим. Reply ставится только на первую часть.
9. По окончании стрима — финальный `sendMessageDraft` с полным `current` не нужен: сразу п. 10.
10. Финализация части: `sendMessage(chat_id, text=to_markdown_v2(part), parse_mode=MarkdownV2)`. Если MarkdownV2 превышает 4096 или Telegram ответил `BadRequest` → повторить plain text без `parse_mode`. Если `part` пустой — не отправлять.
11. Удалить `active[chat_id]` (только если там всё ещё эта же генерация).

Ошибки:

- Исключение Gemini / `TimeoutError` (`GEMINI_TIMEOUT_SEC` на весь стрим) → финализировать накопленное (если есть), затем текст ошибки. Лог `ERROR` с типом исключения, без текста промпта.
- Стрим закончился и итоговый текст пустой (в т.ч. `finish_reason` = `SAFETY`/`PROHIBITED_CONTENT`/`BLOCKLIST`) → `Gemini не вернул ответ на этот запрос.`
- `RetryAfter` на `sendMessageDraft` → пропустить этот draft-апдейт, увеличить интервал до `retry_after`; на стрим модели не влияет.
- Другие ошибки `sendMessageDraft` → лог `WARNING`, стрим продолжается; финальный `sendMessage` всё равно отправляется.

#### Остановка (`on_stop_generation`)

1. Достать `stopped_message_generation` из update (нативное поле или `update.api_kwargs`). Нет поля → `return`.
2. Проверить доступ по `chat` объекта `MessageGenerationStopped` (поля `from` у него нет; в личном чате `chat.id` = user ID, `chat.username` = username). Не private → игнор.
3. Найти генерацию в `active[chat_id]`; нет или `draft_id` не входит в её draft_id (любой из частей) → `return`.
4. `cancel(reason="stopped")`: отменить task чтения стрима Gemini (закрывает HTTP-стрим), финализировать текущую часть как `<накопленное>\n\n⏹ Остановлено` (или только `⏹ Остановлено`, если пусто).
5. Остановить propagation (`ApplicationHandlerStop`).

#### Не текст (`on_non_text`)

Проверить доступ → `Пока я понимаю только текстовые сообщения.`

### Детали: Внешние интеграции

- **Gemini API** (`google-genai`): `client.aio.models.generate_content_stream(model=GEMINI_MODEL, contents=prompt, config=GenerateContentConfig(system_instruction=...))`. Из каждого чанка берётся `chunk.text` (может быть `None` → пропуск).
  - Модель по умолчанию `gemini-3.5-flash-lite` (актуальный stable Flash-Lite на 2026-10-06, дешевле и быстрее); альтернатива `gemini-3.8-flash`.
  - Retry: только если ошибка случилась до первого чанка и она 429/5xx — 1 повтор через 2 с. После первого чанка — без повторов.
  - Тайм-аут: `GEMINI_TIMEOUT_SEC` на весь ответ.
- **Telegram Bot API**: `sendMessageDraft` (только private chats, `draft_id` ≠ 0, текст 0–4096, черновик живёт ~30 с и обязательно фиксируется `sendMessage`), `sendMessage`, `setMyCommands`.

### Детали: Нефункциональные требования

#### Безопасность

- Репозиторий публичный: в git нет `.env`, токенов, ключей, user ID и usernames whitelist. `.env.example` — только имена переменных.
- Не логировать `BOT_TOKEN`, `GEMINI_API_KEY`, тексты вопросов и ответов. Логировать `user.id`, длину ответа, длительность, тип ошибки.
- Whitelist применяется ко всем entrypoints.
- Rate limit на пользователя, чтобы флуд не расходовал квоту Gemini.
- Контейнер от непривилегированного пользователя.

#### Надёжность

- Одна активная генерация на чат; новый вопрос отменяет старую.
- Ошибка Telegram при отправке черновика не прерывает генерацию.
- Graceful shutdown: `run_polling(stop_signals=None)` + собственные обработчики SIGINT/SIGTERM в `post_init`: сначала все активные генерации отменяются с финализацией накопленного текста и `⏹ Остановлено`, затем `app.stop_running()`. В compose `stop_grace_period: 20s`.
- `restart: unless-stopped`, логи json-file с ротацией (10m × 3).

#### Совместимость

- Если PTB не знает `can_stop`/`stopped_message_generation` — используются `api_kwargs` (см. Runtime); при обновлении PTB перейти на нативные поля без изменения поведения.

#### UX

- Первая финальная часть — reply на вопрос пользователя.
- Черновик появляется сразу (пустой → «Thinking…»), без ожидания первого чанка.
- Интервал черновиков 300 мс по умолчанию — компромисс между плавностью и лимитами Telegram.

### Детали: Acceptance checklist

- `/start` и `/help` показывают одинаковый текст с актуальным ID модели.
- Текст от разрешённого пользователя → сразу «Thinking…», затем текст растёт в черновике, в конце обычное сообщение с форматированием, reply на вопрос.
- Ответ > 4096 символов приходит несколькими сообщениями без потери текста.
- Кнопка Stop прекращает генерацию; частичный текст сохраняется с `⏹ Остановлено`.
- Новый вопрос во время генерации прерывает предыдущий ответ.
- Невалидный MarkdownV2 не теряет ответ — уходит plain text.
